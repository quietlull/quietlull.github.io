The callout pick

DECIDED - A (Rod, 2026-09-01): "callouts should be A and not use any of the other candidates. the shells should be the same across all versions." The callout plugin (_plugins/callout.rb) now writes the Candidate A markup for every category.

Two systems ship and nobody has chosen between them. The words are the same real paragraph from the Compute Grass post in every box, so only the SHELL differs. Whichever wins, you will never type its class names: the plan is {% raw %}{% callout warning %}{% endraw %} and the plugin writes the rest, so switching later is a one-file change.

Candidate A - the d-callout box (decisions.scss)

One box, colour comes from the category automatically (your D30 colour-by-meaning call written as CSS). Faint paper shadow, gneiss's real 0.05deg rotation, the panel grey. All four categories:

note - one green strip on top
Note

Originally I used a ping-pong buffer to decay the render texture, but a single target with framerate-independent decay in the shader turned out simpler and faster.

tldr - one orange strip down the left
TL;DR

A script bakes blade positions into a buffer once; one compute pass builds the geometry every frame and the camera never sees a blade it culled.

warning - four pink corners
Warning

Smooth the return of the grass in the shader. Without it the blades twitch every time an interactor leaves, and it looks like a physics bug rather than a missing lerp.

quote - blue L-corners, italic
Quote

Every tech artist worth their salt eventually makes their own grass shader.
