Four things you caught, all now fixed, and all four were Rouge lying rather than a colour being wrong. None of them are expressible in CSS, which is why the shipped version needs a build-time pass:

you saidwhat Rouge didthe rule that fixes it
SAMPLE_TEXTURE2D is a function class n; my SCREAMING_SNAKE rule then called it a constant SCREAMING_SNAKE followed by ( is a macro function, not a constant
noise is purple and shouldn't be class nb — HLSL really has a noise() intrinsic, but here it is a local variable a function token not followed by ( is not a call → demote to variable
POSITION/TEXCOORD0 shouldn't be purple nb — the same class as lerp a token preceded by : is a semantic
(found while fixing) SV_Target plain n — so your three semantics rendered THREE different colours same : rule catches all three regardless of Rouge's class

Every rule above is positional, not a word list, so it does not need maintaining per language. One known limit: #define MAX_STEPS 64 is swallowed by Rouge into a single preprocessor span, so nothing inside a #define can be coloured separately.
