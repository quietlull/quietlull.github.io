What the three actually differ on

Only one thing is still open for this component: how much chrome a portrait gets. V1 gives it none, which is the figure decision already locked (catlikecoding, no mat, no border, no fill, left caption) applied to this box. V2 puts a frame on it that is not a box - four 1px elbows, nothing in between, so the scene reads straight through the corners. V3 makes it an object with a title bar that names it, which is the register Rod already picked when he named 109ichiki's windows.

Nothing in this file animates. Two motions were available in the sources and both were dropped on purpose: filipporuffini's arms-grow-on-hover belongs to their cursor, not their frame, and 109ichiki's cursor:grab would promise a drag that a fixed rail cannot deliver. Their [data-blink] is a 10Hz flash and is out under STYLE.md Section J.

The media is a placeholder because .profile-container is flex:0 0 300px with &:empty{display:none} and there is no portrait file in the repo. Swap in <img class="pf__media" src alt> and all three work unchanged - the image will be cropped to fill, which is the one thing the fixed reservation forces on catlikecoding's intrinsic-size premise.
