### B1 — Slap toggles are keyboard-dead — Blocker (2.1.1, Level A)
**Evidence:** all 8 `.slap input[type=radio]` are `display:none` / `tabIndex -1`; the flip is
driven by a JS `.on` class plus a mouse click on `.slap-toggle__flap`. A keyboard user cannot
tab to or operate Breathing / Sparkler / Fireworks (top bar) or Technology / Personal (tools).
Same in the `slap-toggle` extracted component.
**Root cause:** `display:none` was OUR change (the `.on`-class workaround for the unreliable
`:checked ~ .flap` selector) — it removed the radios from the tab order as a side effect.
**Proposal:** restore radio focusability — replace `display:none` with screen-reader-only
positioning (`position:absolute; opacity:0; width:1px;height:1px`) so the radios stay focusable
and arrow-key operable; keep the existing `change`-driven `.on` logic (already wired). Add a
visible `:focus-visible` ring on the control when a radio inside is focused.
**Source:** the YarivFrd slap source uses real focusable radios (our display:none diverged from
it) → restoring is returning to the cited source, not new code. Focus-ring recipe from existing
`_a11y.scss`.

### B2 — No visible focus indicator — Blocker (2.4.7, Level AA)
**Evidence (focus probes):** nav link `outline-style:none`; card link `outline-style:none`;
scene switch `outline-style:none`; kit primary button only `1px solid rgba(255,106,0,.5)` (fails
the 3:1 component-contrast bar too, Rule 66). 156 focusable elements, almost none with a
discernible focus style.
**Proposal:** global `:focus-visible` outline (2px amber `--color-gold`, 2px offset) in the
generic layer; never `outline:none` without replacement.
**Source:** existing `_a11y.scss` `:focus-visible` fallback (amber outline) — lift verbatim into
`extracted/styles/generic.css`.

### M1 — Document structure: no h1 / main / skip link, headings are divs — Major (1.3.1, 2.4.1)
**Evidence:** `h1Count: 0`; first heading in DOM is an H3 (card), then H2s; the hero name
"rodney fan" is `div.logo`; section titles ("what i work with", "the work") are `div.shead`,
not headings; no `<main>`; no skip link.
**Proposal:** hero name → `<h1>`; `.shead` titles → `<h2>` (cards/list/post/about become H2,
their sub-items H3); wrap content in `<main id="main">`; add a skip link as first focusable.
**Source:** existing site templates already ship all four (section-landing/post layouts, the
`_a11y.scss` skip link). Note: aggregate is a lab page — but per the deviations log, lab pages
are still analyzed for a11y, and these patterns must be present in the real templates at
assembly. Recommend fixing at assembly rather than retrofitting the throwaway aggregate.

### M2 — Autoplay loops have no off switch — Major (2.2.2)
**Evidence:** 3 card `<video autoplay loop muted>`, `controls:false`; the scene/breathing
toggles do not pause them. Post media will be the same.
**Proposal:** on motion-off (the existing kill-switch / `prefers-reduced-motion`), `pause()` all
`<video autoplay>`; optionally switch to in-view play. One small module.
**Source:** existing site already pauses the Three.js loop via IntersectionObserver + visibility
(PROJECT-STATUS) — same pattern, applied to video elements.

### M3 — Sticky bar obscures focus/anchors — Major (2.4.11)
**Evidence:** `.s-bar` sticky, 147px tall (three slap toggles wrap to rows), `scroll-padding-top:
auto`. Tabbing to or anchor-jumping to content lands behind the bar.
**Proposal:** `scroll-padding-top` = bar height on the scroll container; ensure focused elements
scroll into the clear. Also reconsider bar height — 147px is ~18% of a phone viewport (Section I,
Principle 4/real estate).
**Source:** CSS one-liner (no external source needed); height is a Rod tuning decision.

### M4 — Reduced-motion only partially honored — Major (2.3.3, adopted hard)
**Evidence:** 4 `prefers-reduced-motion` rule-blocks present (from component CSS); merged-card JS
correctly bails under reduced motion. BUT the aggregate's inline ambient CSS — `bgfade` (12s
infinite bloom cross-fade) and the title/logo glows — has no guard.
**Proposal:** wrap all decorative keyframe animation in `@media (prefers-reduced-motion: reduce)`
overrides (animation:none); the bloom should hold a static frame.
**Source:** existing `_animations.scss` kill-switch + reduced-motion block — same structure.

### m1 — Aggregate list filters not focusable — Minor (2.1.1)
`.s-list .filters .f` are `<span>` in the aggregate (keyboard-dead). The **extracted
`list-controls` component already uses `<button>`** — so this is integration debt, not a new
bug. **Source:** own component; resolved when aggregate consumes it at assembly.

### m2 — Decorative SVG icons not hidden — Minor (1.1.1)
8 `.draw-in-icons .icon` SVGs lack `aria-hidden="true"`; their tool name is in the adjacent
`.lab2` label, so the icon is decorative. **Proposal:** add `aria-hidden="true"`. **Source:**
markup attribute, no code source needed. (Real official SVGs are still owed — parked.)

### m3 — Sub-target tap sizes — Minor (2.5.8)
Nav links 71×**21**, small slap labels 72×**23** — under 24×24. **Proposal:** raise nav link
vertical padding; the slap control as a whole is 27px (the halves are visually fused, partial
spacing exception). **Source:** spacing tuner / token — Rod's call.

### m4 — Sub-10px text — Minor (Section I + 1.4.4)
Bar toggle labels 8.96px, back-read 9.3px, card-meta 9.9px. Not a hard WCAG min, but small for
the body-adjacent role and tight against 200% scaling. **Proposal:** nudge up in the type pass.
**Source:** type/token decision — Rod's call.

### m5 — Flip takeaway hover-only — Minor (1.4.13 / 2.5.1)
Dwell-flip reveals the takeaway with no keyboard path; mitigated because `.card-back` text is in
the DOM (exposed to AT) and the card is a focusable link that navigates to the post. **Proposal:**
acceptable as decorative; if the takeaway is ever the *only* place that content lives, add a
focus-triggered flip. **Source:** existing card JS (add a `focusin` handler mirroring dwell).

### N1 — Text-over-video contrast (the signature risk) — Note (1.4.3)
**Method (Section J):** drew the grass video frame to canvas, sampled luminance across the card
title's bounding region. Raw-frame background luminance range behind the title: **0.004–0.129**.
Gold-deep title luminance 0.439 → worst case **2.73:1** vs the brightest raw pixels, 9.08:1 vs
the darkest. The `.card-cover::after` scrim (transparent → `cover-lo` over the bottom 62%)
composites over the video where the title sits, pulling the real background down to ~0.05 →
**~4.7:1**. The title is large text (1.7rem ≈ 27px) so its bar is **3:1**, which it clears.
**Verdict:** passes, but thin — a brighter clip (or a future non-large label over video) could
dip under. **Proposal (cheap insurance):** raise the scrim's mid-stop alpha (`rgba(11,16,36,.62)`
→ ~.75) or add a short solid plate behind the title. **Source:** own `merged-card` component
(`card-cover::after`) — a value tweak, Rod tunes.
